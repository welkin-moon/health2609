# 一餐一动：健康主题移动应用作品

## 项目简介

一餐一动面向校园生活，帮助学生记录自己真正吃了什么、吃了多少，以及当天的体育课和校外运动。学校提供菜单与课程事实，学生确认实际餐食，手机提供授权读取的运动汇总。家庭餐照片可以生成可编辑候选；人工确认后才保存。

本次成果是可安装的 Android 应用、学校管理网页、可运行的演示服务、源码与测试记录。验收目标是演示和测试闭环，不宣称已经建设真实学校的生产系统。

## 可展示功能

1. 学校管理员维护午餐菜单、标准份、可选营养数据及在校时段。
2. 学生通过 0–2 份滑块或可选精确克数记录校园餐；保存后能重新读取。
3. 家庭餐支持相机、相册、人工录入；照片识别结果可修改后确认保存，失败不提交候选。
4. 运动页区分体育课、手机汇总和手动记录；不把步数换算成已发生的运动分钟。
5. 学生可以保存年龄、身高、体重等本机资料，并调整主题与壁纸配色。
6. 管理台显示校园餐参与率、菜品完成度、校园餐营养均值、体育课记录覆盖率和近七天活动趋势。
7. 小样本的营养均值隐藏，避免在展示中暴露单个学生的营养明细。
8. 首页展示能量平衡：估算全天消耗减去已记录摄入；消耗与可选摄入目标在应用设置的「能量设置」统一编辑。

## 计算与记录口径

- 校园餐营养 = 标准份营养 × 学生确认的份量倍率；填写克数时优先按标准克数换算。
- 家庭餐营养来自已确认候选；照片中的隐藏配料、烹饪用油和重量仅能估算，不能当作精确测量。
- 手动餐食没有营养数据时仍保存食物与克数；首页明确说明未知部分，不把未知营养当成完整摄入。
- 能量平衡 = 估算全天消耗 − 已记录摄入；正值显示估算缺口，负值显示估算盈余。未记录餐食时不显示完整的全天缺口。未知营养存在时显示缺口上界或盈余下界。
- 全天消耗可手动填写并保存在本机。19 岁及以上、已指定男/女性别的保存资料可采用 Mifflin–St Jeor 基础代谢 × 1.4 的轻活动粗略估算；默认成长阶段资料不套用成人公式。该值已包含活动，不再叠加手机或手动运动热量。可选摄入目标是独立计划，不作为消耗。
- 估算依据：[Mifflin–St Jeor 成人研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)、[FAO 活动水平定义](https://www.fao.org/4/y5686e/y5686e07.htm)。全天消耗是假设值，结果会随餐食补记改变。
- 校内活动采用学校实际记录或学生选定的手机体育课时段记录，两者不相加。
- 校外活动取手机汇总与手动总分钟中较大者，这是演示版的保守纠错口径，尚未实现按每条运动时间精确去重。
- 管理台营养均值仅统计校园餐；学生当天摄入还包括家庭餐，两种范围有明确标签。
- 饮食和运动建议用于一般记录与健康意识展示，不提供疾病诊断；未成年学生不使用成人体重分级或自动减脂目标。

## 已知边界

- 账号、跨设备加密备份和恢复尚未开放，不作为已实现功能展示。
- 当前使用共享演示身份和客户端演示角色头；学校标识用于演示数据范围，不构成生产鉴权。
- 餐食和运动保存在试用服务，身体资料和外观保存在本机；不能声称全部个人数据已端到端加密。
- Health Connect 是否可读取取决于 Android 版本、提供程序、授权及实际运动记录。不可用时演示手动记录，不伪造手机或手环数据。
- 照片识别依赖外部模型及常驻桥接；有过区域拒绝和间歇失败。提交前应验证服务，失败时展示保留草稿和人工记录路径。
- iOS、鸿蒙和 OpenHarmony 本次不作为已验收成果。
- 所有演示样本为合成测试资料，统计人数不代表真实用户或实际学校成效。

## 本地复现

需要 Node.js 22.13+、pnpm 10、Android 构建所需 JDK17 与 Android SDK。以下步骤只操作本地 D1。

```powershell
pnpm install
pnpm check
pnpm test
cd services/api
pnpm exec wrangler d1 migrations apply health2609 --local --persist-to ../../work/demo-state
pnpm exec wrangler dev --local --ip 127.0.0.1 --port 18790 --inspector-port 18791 --persist-to ../../work/demo-state
```

保持服务终端运行，另开终端在仓库根目录：

```powershell
node tools/prepare-demo.mjs
$env:VITE_API_BASE_URL='http://127.0.0.1:18790'
pnpm --filter @health2609/admin-web dev --host 127.0.0.1 --port 5174
```

准备脚本只允许 loopback 地址，按运行当天准备菜单（已有菜单不覆盖），为两个合成学生准备记录，保留主要演示学生的输入。照片识别需要已有 AGY 服务与本地未追踪的凭据配置；不在提交包中携带密钥。没有识别服务仍能完整演示人工记录与失败恢复。

## 60 秒现场讲解

- 0–10 秒：管理员当天菜单与体育课实际分钟。
- 10–25 秒：Android 选择实际食用量、保存并查看当天反馈。
- 25–38 秒：添加手动运动，说明手机授权读取与在校时段排除。
- 38–50 秒：展示家庭餐已识别候选或手动录入，修改份量后保存。
- 50–60 秒：管理员看板查看记录参与率与趋势。

照片分析通常需要几十秒；可先录制真实完整识别流程，再在一分钟视频中跳过等待并标注。不得用伪造结果代替真实功能。实际交付视频、设备版本、截图和未通过项以验证报告为准。
